# Focused correction pass - source validation

**Status: Historical development record for an earlier V2 correction. For the frozen V3.2 behavior, see [README.md](../README.md) and [V3.2 software verification](RECOVERY_V32_SOFTWARE_VERIFICATION.md).**

The previous Phase 1A gate set `pivotSweepVerified=false` for every Manual command, so the Manual gate rejected both Left and Right. The corrected gate uses front IR, fresh near-front ultrasonic and available side-inspection obstruction as vetoes; the operator supervises unsensed turning. Forward obstacle blocking and held supervised Reverse remain.

The previous Phase 1B `selectPathAfterScan` branch for `EscapeV2` always called `enterV2TrappedHold`. The corrected branch calls the pure `decideV2Scan` function and drives `StuckRecoveryV2Policy` committed-side and turn counts through `beginV2Turn`, `updateSpinTurn`, `finishRecoveryAfterSettle`, `beginV2TrialFrontCheck` and `updateV2Trial`. The normal 35-degree target remains in the non-V2 branch. `AUTO_V2_PROVISIONAL_TURN_TARGET_DEG` is used in the operational gyro completion test and telemetry.

The default V2 flag is OFF. With ON, a finite, fresh L/F/R scan selects a side; after each V2-only gyro increment, a full new scan verifies whether a guarded short forward trial is provisionally reasonable. Failed clearance continues in the committed direction up to a bounded limit. A fresh scan is required before trying the opposite side. An invalid scan, stale IMU, unsafe IR, timeout or exhausted budget enters a latched motor-off assistance hold. A hazard aborts V2 into the existing AUTO hazard clearance path. Operator STOP and mode changes preempt motion. Loss of a previously present Wi-Fi transport or a previously active AUTO dashboard telemetry poll stops V2. The AUTO poll is an unauthenticated link signal, not identity authentication; AUTO without a browser remains autonomous.

Provisional settings: V2 increment 25 degrees, median front clearance >=50 cm from three finite samples with <=5 cm spread, side rays >30 cm, 250 ms forward trial, 3 turns per side, 6 total turns, 2,500 ms turn timeout, 30,000 ms total timeout, 2,500 ms AUTO dashboard poll timeout when one was active at V2 start. These are software gates, not a body-width map, measured translation, guaranteed collision clearance, or calibrated angles. Existing short normal AUTO reverse is unchanged and rear sensing remains absent.

Validation gate: `pio run -e esp32-s3-n16r8` passed with V2 temporarily ON (58,708 bytes RAM; 1,035,341 bytes flash) and then passed with the exact source restored to default OFF (58,708 bytes RAM; 1,033,893 bytes flash). No compiler warnings appeared in either final build. Native MinGW tests: `manual_override_policy`, `manual_motion_gate`, `stuck_recovery_v2_policy`, `trace_ring`, `trace_checksum`, and `v2_recovery_integration` passed with C++11, `-Wall -Wextra -Werror`. Python trace capture checksum/schema test passed. Embedded dashboard JavaScript parsed in local headless Edge with `new Function(source)`; Node was unavailable. The initial host integration compile lacked Arduino HIGH/LOW constants; the host-only stub was fixed before the passing run. One host-test run overlapped the temporary V2-ON source toggle and its default-OFF assertion failed; a sequential rerun after byte-for-byte restoration passed all tests. Integration tests execute the pure decision/policy seam used by NavigationManager, with simulated actuation and sensor results; they do not execute physical peripherals or measure motion.

No firmware was flashed or physically tested. Supervised checks remain for Manual turn direction and IR veto, STOP/dead-man under motion, ~25-degree turn calibration, 50/30 cm provisional clearance against the actual robot footprint, forward-trial stopping distance, hazard preemption, IMU and ultrasonic faults, Wi-Fi loss, trace output, and the existing blind AUTO reverse.
